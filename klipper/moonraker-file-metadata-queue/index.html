1. file_manager 根目录模型与文件系统监听

在 Klipper 生态中，切片文件上传、配置文件在线编辑、日志下载等操作并非直接读写宿主机任意路径，而是由 Moonraker 的 file_manager 组件统一以虚拟根目录（Root）的形式对外提供沙箱化访问。

1.1 核心根目录与权限隔离

Root 名称 默认物理路径 访问权限 用途说明
gcodes ~/printer_data/gcodes 读写 存放 .gcode 切片文件及 .thumbs/ 缩略图目录
config ~/printer_data/config 读写 存放 printer.cfg、moonraker.conf 及子配置文件
logs ~/printer_data/logs 只读 存放 klippy.log、moonraker.log 等运行日志
timelapse ~/printer_data/timelapse 读写（插件注册） 存放延时摄影视频与帧缓存

file_manager 在接收客户端路径请求时，会做严格的路径规范化与越权校验（防止 ../ 目录穿越），并将虚拟路径映射到对应的物理根目录。

1.2 基于 inotify 的文件变更同步

除通过 Moonraker HTTP API 上传或删除文件外，用户还可能通过 SFTP、SCP 或 Samba 直接向 gcodes 目录拷贝文件。Moonraker 使用 Linux 内核的 **inotify**（inotify_simple）机制实时监控已注册根目录：

  1. 当外部向 gcodes/ 写入新 .gcode 文件并触发 IN_CLOSE_WRITE 或 IN_MOVED_TO 事件时，file_manager 会捕获变更。
  2. 若属于 gcodes 目录下的切片文件，立即触发异步元数据提取任务。
  3. 解析完成后，通过 WebSocket 向所有已连接客户端广播 notify_filelist_changed 事件，前端列表无需手动刷新即可自动出现新文件及其缩略图。

2. metadata.py 异步解析流水线

现代多色或高精细度模型的 .gcode 文件体积动辄达到数十甚至数百 MB。如果在 Moonraker 主事件循环中直接扫描文件文本和解码图像，会严重阻塞 Tornado 服务。为此，Moonraker 将元信息提取拆分为独立子进程执行。

2.2 元数据缓存与失效判断

提取出的元数据会持久化保存在 Moonraker 的本地数据库（gcode_metadata 命名空间）中。每次查询或扫描目录时，Moonraker 会比对文件的 size（文件大小）与 modified（修改时间戳）：

  • 两者一致时直接命中数据库缓存，实现千级文件列表毫秒级返回；
  • 任一发生变化（如重新切片覆盖同名文件），自动淘汰旧缓存并重新触发 metadata.py 解析，同时清理旧的 .thumbs/ 缓存图。

3. job_queue 与 history 业务协同

面向多任务连续生产或自动化排产场景，Moonraker 提供了 job_queue（打印队列）和 history（打印历史）两个协同组件。

3.1 job_queue 状态机

状态 (queue_state) 含义 触发条件 / 行为
ready 队列运行中且当前无阻塞 若打印机处于 standby 且队列非空，自动弹出队首任务下发打印
loading 正在加载下一个任务 已向 Klippy 发送 SDCARD_PRINT_FILE，等待任务进入打印态
starting 过渡等待期 当配置了 job_transition_delay 时，上个任务结束后进入倒计时延迟
paused 队列暂停 队列中保留待打任务，但不会自动启动下一个任务（异常中断时自动切入此态）

在 moonraker.conf 中可通过 [job_queue] 控制启动与衔接策略：

当 automatic_transition: True 时，前一个任务状态变为 complete 并经过 job_transition_delay 秒后，队列自动启动下一个任务（常用于配合自动取件机构或传送带机型）。

3.2 history 任务追踪

history 组件通过监听 Klippy 的 print_stats 状态流转，在任务开始时创建一条历史记录，并在任务终止时记录最终结果与资源消耗：

  • 终态分类：completed（正常完成）、cancelled（用户取消）、error（G-code/热端报错中断）、klippy_shutdown（底层停机）。
  • 统计聚合：除单条任务明细（文件名、开始/结束时间、打印耗时、消耗耗材毫米数、关联元数据快照）外，history 还会持续累加全局汇总指标（total_jobs、total_time、total_filament_used），便于上位机直接展示设备累计运行里程。
