1. 分层架构与进程边界

在典型的 Klipper 生态部署中，上位机（Linux SBC）通常同时运行三个核心角色：前端界面（Mainsail / Fluidd / KlipperScreen）、API 网关服务（Moonraker）以及打印核心进程（Klippy）。

各层职责划分如下：

层级 进程 / 组件 核心职责 对外通信方式
表现层 Mainsail / Fluidd / KlipperScreen UI 渲染、文件管理视图、用户交互 HTTP / WebSocket (JSON-RPC)
网关层 Moonraker (基于 Tornado) 鉴权、文件服务、队列管理、协议转发与状态缓存 HTTP + WebSocket 对外；UDS 对内
核心层 Klippy (klippy.py) G-code 解析、运动学规划、步进脉冲调度 Unix Domain Socket 对上；串口 / CAN 对下
硬件层 MCU 固件 (STM32 / RP2040 等) 定时执行步进脉冲、ADC 采样、PWM 输出 USB CDC / UART / CAN

Klippy 本身不直接暴露 HTTP 或 WebSocket 接口，所有外部控制端均通过 Moonraker 间接与 Klippy 交互。这样设计的好处在于将实时运动控制与网络 IO / 文件管理 / 第三方插件解耦，避免网络阻塞影响 Klippy 主事件循环的调度精度。

2. 传输层：Unix Domain Socket 与帧定界

Moonraker 与 Klippy 运行在同一台宿主机上，两者通过 Unix Domain Socket (UDS) 建立本地全双工流式连接，从而绕过 TCP/IP 协议栈开销。

2.2 0x03 (ETX) 帧定界机制

由于流式套接字（SOCK_STREAM）本身没有消息边界，Klippy 的 webhooks.py 约定每条 JSON-RPC 报文必须以 ASCII 控制字符 ETX (0x03) 作为结束符。

Moonraker 内部通过 Tornado 的 IOStream.read_until(b'\x03') 异步读取完整报文，避免粘包和半包解析错误。

3. 协议层：JSON-RPC 2.0 与端点映射

Moonraker 对客户端暴露的是带命名空间的 JSON-RPC 方法（如 printer.info、printer.gcode.script），而 Klippy 内部的 webhooks 模块注册的是以斜杠分隔的端点路径（如 info、gcode/script）。Moonraker 在转发时会完成这层方法名映射。

3.1 常见端点映射对照

Moonraker WebSocket 方法 Klippy UDS 端点 用途
printer.info info 获取 Klippy 版本、运行状态 (ready / shutdown / error)
printer.objects.list objects/list 列出所有已注册的可查询打印机对象
printer.objects.query objects/query 单次拉取指定对象的当前状态
printer.objects.subscribe objects/subscribe 订阅对象状态变化并接收增量推送
printer.gcode.script gcode/script 执行单条或多行 G-code 脚本
printer.emergency_stop emergency_stop 立即触发 MCU 急停

4. 状态订阅与增量推送模型

为了避免前端高频轮询带来的额外开销，Klippy 提供了基于 objects/subscribe 的发布-订阅机制。

4.1 订阅流程

Moonraker 在与 Klippy 建立 UDS 连接并确认 ready 状态后，会代表所有活跃客户端向 Klippy 发起 objects/subscribe 请求，并附带 response_template：

  • 将字段列表设为 null 表示订阅该对象下的全部可读属性。
  • response_template 指定了 Klippy 后续主动推送数据时使用的 JSON-RPC 通知方法名。

4.2 增量 Diff 推送

订阅成功后，Klippy 内部的定时器会以固定周期（默认约 250ms）对已订阅对象的 get_status(eventtime) 返回值做快照比对：

  1. 首次响应：通过对应 id 的 result 返回订阅对象的完整初始状态。
  2. 后续推送：仅当某些字段的值发生变化时，Klippy 才会通过 UDS 主动发送无 id 的通知报文，且只包含发生变化的字段：

Moonraker 收到该通知后，先更新本地维护的状态缓存字典，再按各 WebSocket 客户端各自订阅的字段子集进行过滤与分发。

5. 使用 socat 直连调试 UDS

在排查 Moonraker 与 Klippy 之间的通信异常（如 Klippy 启动卡死、Web 接口无响应但打印机仍在运动）时，可以直接使用 socat 绕过 Moonraker 与 Klippy 通信，定位问题归属。
