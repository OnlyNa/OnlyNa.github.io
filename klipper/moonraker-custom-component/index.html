1. 组件发现机制与生命周期

Moonraker 采用高度模块化的 Component 架构。除内置核心组件外，开发者可以编写自定义 Python 组件并接入 Moonraker 的事件总线、HTTP REST 路由及 WebSocket JSON-RPC 体系。

1.1 模块映射与加载入口

当 moonraker.conf 中出现一个配置段（例如 [custom_stats]）时，Moonraker 会按以下规则自动查找并加载组件：

  1. 提取配置段名称作为模块名（带空格的多实例段如 [power relay_1] 会取前缀 power）。
  2. 在 moonraker/components/ 目录下查找 custom_stats.py（或同名包目录）。
  3. 调用模块内必须导出的工厂函数 load_component(config: ConfigHelper)，返回组件实例。

1.2 组件生命周期阶段

阶段 触发时机 同步 / 异步 典型操作
__init__(self, config) 解析 moonraker.conf 加载组件时 同步 读取配置参数、查找依赖组件、注册 HTTP/JSON-RPC 端点与事件监听
component_init(self) 所有组件实例化完毕、服务启动前 异步 (async def) 初始化数据库命名空间、建立外部网络/串口连接、启动后台异步任务
close(self) Moonraker 进程退出或重载时 异步 (async def) 取消后台 Task、关闭文件句柄与外设连接、落盘缓存状态

2. 核心服务端 API 能力矩阵

组件在 __init__ 中通过 config.get_server() 获取 Server 单例，常用的核心接口如下：

对象 / 方法 作用 说明
config.get() / getint() / getboolean() 读取当前组件配置项 支持默认值与类型校验，缺失必填项时直接抛出 config.error
self.server.lookup_component(name) 获取其他已加载组件实例 如 klippy_apis、database、file_manager、job_state
self.server.register_endpoint(uri, request_types, callback) 注册 API 端点 单次注册即可同时通过 HTTP REST 与 WebSocket JSON-RPC 访问
self.server.register_event_handler(event, callback) 订阅内部事件 如 server:klippy_ready、server:status_update、job_state:started
self.server.register_notification(event_name, notify_name) 映射内部事件到 WebSocket 推送 将服务端内部事件自动广播给已连接的 WebSocket 客户端
self.server.send_event(event, *args) 触发自定义内部事件 供其他组件订阅或配合 register_notification 对外推送

其中 register_endpoint 是最关键的扩展点：若注册 URI 为 /server/custom_stats/summary，客户端既可以通过 GET http://<host>:7125/server/custom_stats/summary 请求，也可以通过 WebSocket 发送 {"jsonrpc": "2.0", "method": "server.custom_stats.summary", "id": 1} 调用同一处理函数。

4.2 异步编程避坑要点

Moonraker 全程运行在基于 Tornado / asyncio 的单线程事件循环中，编写组件时需注意以下约束：

  1. 禁止在协程中执行阻塞 IO：不可在 async def 回调里直接调用 time.sleep()、requests.get()、阻塞式串口读写或大文件同步读写，否则会冻结整个 Moonraker 服务的响应与 WebSocket 心跳。必须改用异步库（如 aiohttp）或通过 self.server.get_event_loop().run_in_thread(fn, *args) 投递到工作线程池执行。
  2. 避免直接操作未就绪的 Klippy 接口：组件启动时 Klippy 可能尚未完成握手，调用 klippy_apis 应在 server:klippy_ready 回调之后进行，或做好 ServerError 异常捕获。
  3. 升级兼容性：Moonraker 默认启用 Git 仓库完整性校验，若直接向 ~/moonraker/moonraker/components/ 放入未跟踪文件，更新管理面板（update_manager）会提示仓库存在脏文件（dirty），生产环境中建议通过软链接或独立包方式维护自定义组件。
